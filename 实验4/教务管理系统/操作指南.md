# 教务管理系统 操作指南

> 数据库系统原理 · 实验四「数据库设计」配套应用程序
> 系统名称：学生选课管理系统（教务管理）
> 开发方式：Python（PyMySQL 嵌入式 SQL）后端 + 原生 HTML/JS 前端

---

## 1. 系统结构

后端共 **5 个 Python 模块，一个文件一个职责**，调用方向自上而下：

```
app.py（界面层）→ services.py（业务层）→ models.py（实体层）
                                ↘ database.py（数据层）→ MySQL
                    config.py（配置层，被以上各层读取）
```

```
实验4\教务管理系统\
├── .venv\               ★ 项目专用 Python 解释器（虚拟环境，含依赖）
├── app.py               界面层：HTTP 服务 + REST 路由 + 程序入口（python app.py）
├── services.py          业务层：六大功能的嵌入式 SQL + 双重验证第二重
├── models.py            实体层：Student/Course/Enrollment 实体 + 第一重校验
├── database.py          数据层：连接管理/事务 + MySQL 错误翻译
├── config.py            配置层：数据库连接、端口、路径（★ 唯一可能需要你修改的文件）
├── schema.sql           建库脚本：四表 + 完整性约束 + 示例数据（在 DataGrip 执行，Python 不做建表）
├── static\index.html    前端单页：主页七个功能按钮与全部交互
├── check_env.py         环境自检：解释器/依赖/MySQL/库表/服务状态一键检查
├── requirements.txt     依赖清单（仅 pymysql）
├── test_api.py          API 集成测试（78 项用例，含成功/失败用例）
├── test_constraints.py  数据库完整性约束验证（9 项非法数据用例）
├── 启动系统.bat          双击：自检 → 启动服务 → 打开浏览器
└── 运行测试.bat          双击：自检 → 恢复数据（MySQL 端执行 schema.sql）→ 跑两套测试
```

与实验报告设计的对应关系：

| 报告 5.1 需求分析的功能 | 页面按钮 | 后端接口 |
|---|---|---|
| 1. 学生信息维护（录入新生） | ① 录入新生信息 | `POST /api/students` |
| 1. 学生信息维护（修改信息） | ② 学生信息修改 | `PUT /api/students/{学号}` |
| 2. 课程信息维护（含先修课） | ③ 课程信息维护 | `POST/PUT/DELETE /api/courses` |
| 3. 成绩管理（录入、修改） | ④ 成绩录入修改 | `POST /api/grades` |
| 4. 按系统计成绩 | ⑤ 统计成绩信息 | `GET /api/stats` |
| 5. 按系成绩排名 | ⑥ 按系排名 | `GET /api/rank` |
| 6. 按学号查询 | ⑦ 学生信息查询 | `GET /api/students/{学号}` |
| （扩展）删除学生信息 | ⑧ 删除学生信息 | `DELETE /api/students/{学号}` |

数据库四个关系模式与报告 5.3 逻辑设计一致：
学生 `Student( Sno, Sname, Ssex, Sage, Sdept, Scholarship )`、
课程 `Course( Cno, Cname, Ccredit )`、
选课 `SC( Sno, Cno, Grade )`、
先修 `CP( Cno, Cpno )`。

## 2. 环境准备与启动

环境要求：Python 3.10+、MySQL 8.x、PyMySQL（唯一第三方依赖，见 `requirements.txt`）。

**项目解释器（已配置好）**：项目使用虚拟环境 `.venv` 作为专用解释器，
路径为 `.venv\Scripts\python.exe`（Python 3.15 + PyMySQL 已装入其中，与系统环境隔离）。

- 命令行使用：`cd 教务管理系统` 后执行 `.venv\Scripts\activate` 激活，或直接调用完整路径
- VS Code：打开项目文件夹 → `Ctrl+Shift+P` → "Python: Select Interpreter" →
  输入 `.venv\Scripts\python.exe`
- PyCharm：`File → Settings → Project → Python Interpreter → Add Interpreter →
  Add Local Interpreter → Virtualenv → Existing` → 选择 `.venv\Scripts\python.exe`

重建虚拟环境（如需）：`python -m venv .venv` 然后
`.venv\Scripts\python.exe -m pip install -r requirements.txt`

**方式一：双击即用（推荐）**

| 文件 | 作用 |
|---|---|
| `启动系统.bat` | 环境自检 → 启动服务 → 自动打开浏览器 |
| `运行测试.bat` | 环境自检 → 自动启动服务（如未启动）→ 在 MySQL 端执行 schema.sql 恢复初始数据 → 依次跑 `test_api.py`（78 项）和 `test_constraints.py`（9 项）→ 结束后自动恢复初始数据 |

**方式二：命令行**


## 4. 双重验证机制说明（报告可引用）

非法数据要过两道关，任何一道拦下都会给出中文提示和合法范围：

**第一重：Python 应用层校验（models.py）**
在数据发往数据库之前检查格式与范围：学号 9 位数字、性别∈{男,女}、年龄 1～150 整数、学分 0～10 的数（最多两位小数）、成绩 0～100 整数或空、课程号 1～4 位字母数字等。绝大多数非法输入在这里被直接拒绝。

**第二重：数据库完整性约束（schema.sql，DBMS 保证）**

| 约束 | 作用 | 违反时的 MySQL 错误码 |
|---|---|---|
| `pk_student` / `pk_course` / `pk_sc` | 主码唯一 | 1062 |
| `uk_student_sname` | 姓名（候选码）唯一 | 1062 |
| `ck_student_sex` / `ck_student_age` / `ck_sc_grade` / `ck_cp` | 用户定义完整性 | 3819 |
| `fk_sc_*` / `fk_cp_*` | 参照完整性（外键） | 1452 / 1451 |

服务层 `services.py::_integrity_to_biz()` 把这些错误码翻译成中文提示，因此即使绕过前端和 Python 校验（例如并发插入重复学号），数据库也会拒绝并返回友好信息。

验证脚本（可直接运行，输出可作为报告功能测试证据）：

```powershell
python test_api.py          # 62 项 API 用例：七大功能 + 各类失败用例
python test_constraints.py  # 9 项用例：直接向数据库写非法数据，全部被约束拒绝
```

## 5. 常见问题

| 现象 | 解决 |
|---|---|
| 右上角状态灯为红色「连接异常」 | 后端没启动：`python app.py`；或看下方 500 报错 |
| 提示「数据库错误 / Access denied」 | 改 `config.py` 里的 `user/password` |
| 提示「Unknown database 'sms'」 | 在 DataGrip 中执行 schema.sql 建库 |
| 端口被占用 | `python app.py --port 9000`，浏览器访问对应端口 |
| 中文乱码 | 确认 `config.py` 的 `charset` 为 `utf8mb4`（默认已设） |
| 想恢复初始数据 | 在 DataGrip 中重新执行 schema.sql（会删表重建并重灌示例数据） |

停止服务：在运行窗口按 `Ctrl + C`。
